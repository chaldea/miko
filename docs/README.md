# Documentation and WebAssembly demo

The site is generated by src/Miko.Docs; no Node.js, npm or Vue build is needed.
Miko.Docs.Web/Content is the single source for pages and the reference shipped in app templates.
API regions and Razor examples are checked by tools/Miko.DocGen and tests/Miko.Docs.Demo.Tests; the generator
itself is covered by tests/Miko.Docs.Tests.

## Develop

~~~sh
dotnet run --project docs/Miko.Docs.Web
dotnet run --project docs/Miko.Docs.Demo.Browser
dotnet test tests/Miko.Docs.Tests
dotnet test tests/Miko.Docs.Demo.Tests
~~~

The first command serves documentation at http://localhost:5173/. The second runs the
reserved demo independently using the URL printed by the WebAssembly development server.
The demo is the Miko component playground: a Miko app (docs/Miko.Docs.Demo, Ionic, Charts and
Components) drawn on a canvas by the Miko.Browser host (docs/Miko.Docs.Demo.Browser). It needs the
wasm-tools workload (`WasmBuildNative=true`).

## Publish one static site

~~~sh
dotnet publish docs/Miko.Docs.Web -c Release -o artifacts/docs
pwsh -File docs/Verify-Publish.ps1 -SiteRoot artifacts/docs/wwwroot
~~~

Deploy only artifacts/docs/wwwroot. Publishing the documentation also publishes the browser
head and copies its complete wwwroot into wwwroot/demo/:

~~~text
wwwroot/
  index.html
  assets/
  guide/...
  demo/
    index.html
    _content/Miko.Browser/miko-browser.js
    _framework/...
~~~

For a repository subpath such as GitHub Pages:

~~~sh
dotnet publish docs/Miko.Docs.Web -c Release -o artifacts/docs -p:MikoDocsBasePath=/miko/
pwsh -File docs/Verify-Publish.ps1 -SiteRoot artifacts/docs/wwwroot -BasePath /miko/
dotnet artifacts/docs/Miko.Docs.Web.dll --project artifacts/docs --no-watch
~~~

The last command serves the published artifact at http://localhost:5173/miko/.
Click **Live Demo**, wait for the playground to appear, refresh, and use the browser's back button to return to the documentation.
The development server rebuilds documentation sources; use the published preview for this
combined-site check. The GitHub workflow obtains its base path from configure-pages so
custom domains, root deployments, and repository subpaths use the same publish command.

The Ubuntu publishing job installs the SDK selected by global.json and the matching
wasm-tools workload. Setup .NET alone does not install the Emscripten/native WASM
toolchain. The browser head sets WasmBuildNative=true because SkiaSharp and HarfBuzzSharp
ship native WebAssembly archives; AOT (RunAOTCompilation) is opt-in.
Install the workload before publishing locally:

~~~sh
dotnet workload install wasm-tools
~~~

The documentation workflow publishes and verifies the static site on relevant main-branch
pushes or manual dispatches. Pull requests do not run the Pages workflow. To validate a
pull request locally, publish and verify both /miko/ and / using the commands above.

## Hosting boundaries

- /demo/ is reserved for the browser application. Its page loads the bootstrap through a
  relative URL (`_content/Miko.Browser/miko-browser.js`), which in turn imports `_framework/`, so everything
  stays inside that directory at either deployment base.
- The homepage navigates to a separate document. Documentation styles and JavaScript do not
  run inside the demo. No service worker is installed, so there is no cross-site cache scope.
- Keep the trailing slash on /demo/; static hosts must redirect directory requests to it
  and serve .wasm files as application/wasm.
- The playground routes with the URL hash (`#/...`), so it needs no server fallback. Do not
  redirect documentation 404s to the WebAssembly app.

Verify-Publish.ps1 checks every generated local link, the demo runtime, and both URL spaces.
The documentation test project covers the generator, templates and rendered examples.

Optional browser verification uses an independently installed playwright-core module:

~~~sh
node docs/Verify-Browser.mjs artifacts/docs/wwwroot /miko/ /path/to/playwright-core/index.mjs /path/to/chromium
node docs/Verify-Browser.mjs artifacts/docs-root/wwwroot / /path/to/playwright-core/index.mjs /path/to/chromium
~~~

Publish artifacts/docs-root without MikoDocsBasePath first. This check uses a plain static
HTTP server and verifies real WASM downloads, the playground's first frame, refresh, returning to docs,
the directory redirect, 404 behavior, resource isolation, and mobile homepage layout.
It also checks embedded Shiki syntax highlighting in both themes, Razor/C# and
other bundled languages, multiline comments, line numbers, escaped code, and
copy feedback/content including Clipboard API failure and retry.
Screenshots are written under artifacts/docs-browser. Node is only needed for this optional
contributor check; building and deploying the site remains a .NET-only workflow.

Syntax highlighting, its WebAssembly engine, language grammars and themes are
embedded in Miko.Docs and published under assets/highlight.js. No CDN is used.
Optional regeneration instructions are in src/Miko.Docs/Client/README.md.
